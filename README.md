# Flight Navigator: Backend MVP (MOW → IST/SAW → HKT)

FastAPI бэкенд для навигатора и оптимизатора авиамаршрутов по ключевому коридору для российских путешественников: **Москва (MOW: SVO/VKO/DME) — Стамбул (IST/SAW) — Пхукет (HKT)**.

Сервис решает задачу сравнения **сквозных единых билетов** (`unified`) и **составных связок из двух раздельных билетов (self-transfer)** (`assembly`), рассчитывая честную полную стоимость («корзину») с учётом багажа и мест, контролируя риски пересадки и смены аэропорта, и формируя прозрачные deep-link ссылки на покупку.

---

## 🎯 Продуктовые принципы

1. **Честность сценариев и ориентировочные цены**:
   - Мы не продаём билеты сами и не скрываем риски.
   - Цены из кэша Aviasales Data API называются **«ориентирами»**, так как тарифы в реальном времени и на этапе бронирования могут меняться.
   - Никаких выдуманных или шаблонных рейсов в выдаче: если данных по направлению нет, сервис возвращает явные причины в `empty_reasons` и ссылку на ручной поиск.
2. **Два класса пакетов**:
   - `unified`: единый билет (например, перелёт Turkish Airlines через Новый аэропорт IST). Багаж обычно регистрируется до конечной точки.
   - `assembly`: два независимых билета (например, Москва → Стамбул и Стамбул → Пхукет). Пользователю явно сообщается: при опоздании на первый рейс второй билет сгорает; багаж в Стамбуле нужно забрать и сдать заново.
3. **Пресеты пересадки и контроль смены аэропорта**:
   - Пресеты: `faster` (быстрый), `calm` (спокойный, по умолчанию), `buffer_12h` (с длинным буфером/ночёвкой).
   - Минимальный порог времени для смены аэропорта **IST ↔ SAW составляет 6 часов**. Маршруты с нарушением порогов попадают во вкладку **«Дешевле, но рискованнее»** (`risk`), а не рекомендуются по умолчанию.
4. **Полная корзина (Full-basket pricing)**:
   - Расчёт цены с учётом багажа (`none`, `cabin_only`, `checked_10kg`, `checked_20kg`, `checked_23kg`, `checked_30kg`) и выбора мест.
   - Раздельное отображение `bare_fare_rub` (базовый тариф) и `full_basket_rub` (полная корзина).
5. **Двойной CTA (Dual Call-to-Action)**:
   - Глубокие ссылки на Авиасейлс с партнёрским маркером (`marker=765617`).
   - Для единых билетов: если на сайте авиакомпании цена гарантированно ниже (на ≥5% или ≥1500 ₽), сайт перевозчика становится первичным CTA (`primary`), а Авиасейлс — вторичным (`secondary`).
   - На каждом пакете установлен флаг `disclaimer_required: true`.
6. **Кластеризация близких цен**:
   - Варианты в пределах ±1000 ₽ или ~3% группируются под лидером кластера в `cluster_alternatives`.

## 🔒 Как задать секреты (AVIASALES_TOKEN и AVIASALES_MARKER)

Для работы поиска с реальными данными требуется токен Travelpayouts Aviasales Data API.

### 1. Локально на компьютере (.env)
1. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env
   ```
2. Откройте `.env` и впишите ваш токен Travelpayouts:
   ```env
   # Токен Travelpayouts (Data API). Взять в кабинете Travelpayouts → API
   AVIASALES_TOKEN=ваш_токен_здесь
   # Партнёрский маркер Travelpayouts
   AVIASALES_MARKER=765617
   ```
3. Файл `.env` добавлен в `.gitignore` и никогда не попадает в git.

### 2. В удалённом окружении Cursor Cloud Agent
1. В интерфейсе Cursor перейдите в **Settings / Dashboard → Cloud Agents → Secrets** (или откройте настройки окружения агента).
2. Добавьте переменные:
   - Имя: `AVIASALES_TOKEN`, Значение: `ваш_токен`
   - Имя: `AVIASALES_MARKER`, Значение: `765617`
3. Переменные автоматически подключатся в виртуальную машину агента.
4. **Безопасность**: никогда не отправляйте токен в чат открытым текстом.

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Запуск сервера разработки
```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```
Документация Swagger UI: [http://localhost:8000/api/v1/docs](http://localhost:8000/api/v1/docs).

### 3. Проверка статуса сервиса
```bash
curl -s http://localhost:8000/api/v1/health | jq .
```
В ответе вы увидите поле `aviasales_data_api`:
- `configured: false` — если токен не задан (сообщение с подсказкой).
- `configured: true`, `api_reachable: true` — если токен активен и API отвечает. Значение токена никогда не выводится.

### 4. Запуск автоматических тестов
```bash
pytest -v
```

## 📡 Примеры запросов и API

### 1. Быстрый поиск через GET-запрос (`/routes/quick-search`)
```bash
curl -s "http://localhost:8000/api/v1/routes/quick-search?departure_date=2026-11-10&layover_preset=calm&baggage=checked_20kg&adults=1&include_neighbor_dates=true" | jq .
```

### 2. Полный поиск через POST-запрос (`/routes/search`)
```bash
curl -s -X POST http://localhost:8000/api/v1/routes/search \
  -H "Content-Type: application/json" \
  -d '{
    "departure_date": "2026-11-10",
    "origin": "MOW",
    "hub": "IST",
    "destination": "HKT",
    "layover_preset": "calm",
    "allow_airport_change": true,
    "passengers": {
      "adults": 1,
      "children": 0,
      "infants": 0
    },
    "baggage": "checked_20kg",
    "seats": "none",
    "include_neighbor_dates": true
  }' | jq .
```

## ⚠️ Известные ограничения (Known Limitations)

- **Кэш Aviasales Data API**: сервис агрегирует кэшированные данные цен из Data API Travelpayouts. В кэше могут отсутствовать точные номера рейсов и точное время вылета/прилёта (в таких случаях возвращается `null`, без фантазий).
- **Ориентировочный характер цен**: тарифы отражают недавно найденные пользователями цены и служат ориентиром для выбора сценария.
- **Самостоятельная стыковка**: на всех составных маршрутах пользователь предупреждается о необходимости повторной сдачи багажа и рисках задержки первого сегмента.
